## 二、确认并修复（BUG 登记册）

### BUG-A1 · Major · Integration
- **位置**：`scripts/repair-workspace-accounts.mjs:30`
- **现象**：netstat 存活守卫正则 `/:3080\s+\S+\s+0\.0\.0\.0:0\s+LISTENING/` 假设「本地地址后有两个地址槽」——真实 `netstat -ano` LISTENING 行只有本地/外地/状态三列。**实测正则对本机全部 LISTENING 行零匹配**：守卫永不触发，修复脚本可在 dsh 运行时执行，内存域回写会覆盖修复结果（脚本头注释明确警示的数据丢失场景）。
- **修复**：改为三列格式 `/:3080\s+\S+\s+LISTENING\b/i`，附实测格式注释。
- **验证**：新正则对既有监听零误报、对合成 `:3080` 监听行命中；脚本端到端 dry-run 通过。

### BUG-A2 · Major · Edge Case
- **位置**：`scripts/repair-workspace-accounts.mjs:81`
- **现象**：`realpathSync(record.path)` 无守卫——任一工作区记录指向已删除/改名目录即抛 ENOENT，**整批修复中止**，其余记录不再处理（工具的核心用途恰恰是修复受损状态）。可运行复现确认。
- **修复**：逐条 try/catch 跳过坏记录；`sessionIds` 非数组时按空处理，防受损记录二次中断。
- **验证**：含「1 条有效 + 1 条已删除路径」的临时 home 上 dry-run：有效记录被修复、坏记录被跳过、退出码 0。

### BUG-A3 · Minor · Edge Case
- **位置**：`scripts/repair-workspace-accounts.mjs:77`
- **现象**：`workspace.json` 损坏时 `JSON.parse` 裸抛栈，无任何处置指引。
- **修复**：捕获后输出「从 *.bak-* 恢复或手工修复」指引并以退出码 1 终止。

### BUG-B1 · Major · Error Handling
- **位置**：`lib/client.js:5788`（ChProjectTab）
- **现象**：挂载期 `sessionAdmin/list` 失败被空 `.catch(function () {})` 吞掉——会话下拉静默空白，无任何反馈；而同组件的 `load()` 走 `setError(messageOf(e))` 正常上报（通道现成）。
- **修复**：`.catch(function (e) { setError(messageOf(e)) })`。
- **验证（TDD）**：self-check 新增 15d 故障注入断言（`ctx.sessionListFail` 桩）先红后绿；全量回归通过。

### BUG-C1/C2 · Minor · CI
- **位置**：`.github/workflows/ci.yml` / `release.yml`
- **现象**：无 concurrency 组——CI 过期 push 叠跑浪费 runners；Release 并发 tag 可竞态 npm 发布。
- **修复**：CI `cancel-in-progress: true`；Release 串行组（不取消进行中的发布）。

## 五、模式归纳与预防建议（Phase 7）

1. **死守卫模式**（本轮最重）：安全正则按想象中的格式书写，从未对真实输出验证。预防：每个守卫正则旁附一条真实格式样例注释 + 一次性对真实数据验证；repair 类脚本建议纳入 CI 可跑的 dry-run 烟测。
2. **静默 catch 不对称**：同一组件一条路径上报错误、另一条吞掉。预防：约定「面板挂载期 RPC 一律到达 setError/showToast」，可用 ESLint `no-empty-callback` 类规则扫 `.catch(function () {})`。
3. **维护脚本鲁棒性**：批修复循环必须逐条容错，单条坏数据不得中断整批。
4. **多 agent 审查的矛盾裁决**：4 份报告出现 3 处互相矛盾的断言，全部靠读源码裁定。预防：任何发现入册前过「锚定→证据→定级」硬门（本轮拦截 9 项）。
5. **测试桩故障注入**：`ctx.*` 覆写模式（`sessionListFail`）已扩展，建议为每个 RPC 命名空间预留失败注入位，覆盖「加载失败」路径。
